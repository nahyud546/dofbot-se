Audit on 2026-10-06 of `t8_assistant.py --vision-backend ros3d` and `cube_search_center.py` (user goal: pick from any start pose, not only Yahboom's READY_POSE [90,125,0,0,90]).

Measured root causes (IK probe on isolated ROS_DOMAIN_ID=88, no motors):
- `dofbot_info/src/dofbot_kinematics.cpp` is a KDL re-implementation, not Yahboom's closed lib. Clients always request RPY (0, 1.04, -pi). The exact 6D solve never converges on this 5-DOF arm (1 of 312 solutions near requested pitch); every answer comes from the random-restart position-only fallback (3 mm tol, pitch +-0.35 rad).
- Result: only 312/728 grid points in the gated workspace solve; at z=0.047 the usable band is roughly x in [-0.19,-0.11]. Geometrically the arm reaches r=0.06-0.30 if gripper pitch is allowed to vary with reach (about 0 deg tilt at r=0.10, 30 deg at 0.20, 50 deg at 0.25).
- IK is independent of the start pose; the start-pose dependence comes from vision: T8 ros3d always runs `fixed_ready_pose` (Yahboom linear pixel map) because `cube_6d_urdf.yaml` has `calibrated: false`.
- `cube_search_center_math.py`: ray is intersected with the table plane although the tracked pixel is the tag on the cube top (+30 mm) -> 40-55 mm XY error; `MOUNT_PITCH_CORR_DEG=14` is a single-point fit; table height disagrees between files (0.030 vs 0.045); workspace gate is a base-frame rectangle though J1 sweeps 20-160 deg.

Done 2026-10-06 (code only, not yet run on the real arm): step 1 implemented as `projects/t8_pipeline/dofbot_ik.py` (analytic FK/IK, used by `t8_motion_worker.Kinematics` and `cube_search_center._LiveKin`; ROS IK service no longer needed), plus polar `check_workspace`. Not done: tag-height plane fix (needs MOUNT_PITCH re-fit from measurements) and camera calibration.

Also done 2026-10-06 (code + simulation only): `projects/vision_experiments/calibrate_hand_eye.py` (arm self-moves, bundle-adjusts mount from the cube AprilTag, writes `config/robot/hand_eye.json` + `config/robot/cube_6d_calibrated.yaml`); search-center loads it and intersects at tag height; T8 auto-uses the YAML, uses calibrated base poses for all picks and skips READY_POSE (`prepare keep_pose`). Key finding: Arm_Lib truncates servo readback to integer degrees; raw counts (`arm.servo_H/L`) give 0.08 deg and cut simulated calibration error from ~6-15 mm to ~1-3 mm (`fine_angle`). Still open: user must run the calibration on the real arm; any real TCP offset and T8's rectangular workspace gate are untested/unchanged.

First real calibration run 2026-10-06 (16 samples, `config/robot/hand_eye_samples.json`) showed: in the IK joint convention the camera sits at arm4 x = +40 mm (URDF/old model said -48 mm), optical axis parallel to the link (the old 14 deg pitch fudge was compensating the sign error); lens is fx~896, fy~941, k1~-0.5 (not 902/875/0). Solver now fits fy/fx + k1 and anchors tag height to 0.061 m. Result: held-out table-XY error <= 2 mm in all 4 cross-validation folds (search-center calibrated mode ON via hand_eye.json), agrees with the proven legacy pixel map within ~2-4 mm at image centre. The PnP-3D check for T8 perception was borderline (5.0-6.5 mm vs 5 mm gate), so `cube_6d_calibrated.yaml` is NOT written yet; asked user to recollect with the wider pose grid (default 24 samples).
